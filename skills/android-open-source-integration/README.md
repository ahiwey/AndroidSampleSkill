# Android 开源项目集成

`android-open-source-integration` 用于把 GitHub 上的 Android 开源项目代码以可追溯、可访问、可关闭和可移除的方式集成到现有应用。

> 该 Skill 面向真实功能集成，不用于制造死代码、不可达页面、虚假分支或规避代码审查。

## 何时使用

- 将两个或三个开源 Android 项目的页面或功能加入当前应用。
- 引入开源模块、资源、依赖或完整功能子包。
- 需要统一的 Application 总开关和清晰的移除标记。
- 需要同时处理许可证、来源记录、资源命名和入口可达性。

## 快速使用

先让 Codex 搜索候选项目：

```text
使用 $android-open-source-integration 为当前 Android 应用搜索 10–15 个适合集成的 GitHub 开源项目，只输出候选表，等我确认来源后再继续。
```

确认来源后，再要求生成实施预算并等待确认：

```text
我选择候选 2、5、8。继续使用 $android-open-source-integration 输出文件、资源、依赖、入口和移除方案预算，不要立即修改代码。
```

## 能做什么

| 阶段 | 主要工作 |
| --- | --- |
| 项目盘点 | 识别包名、Application、Manifest、Gradle、源码和资源结构。 |
| 候选筛选 | 基于许可证、活跃度、功能完整度和可集成性筛选 GitHub 项目。 |
| 实施预算 | 估算文件、资源、依赖、Manifest、R8、入口和移除成本。 |
| 等价集成 | 按现有项目分层和命名风格导入页面、功能、资源与依赖。 |
| 开关治理 | 通过自定义 Application 总开关控制所有新增入口。 |
| 来源记录 | 记录仓库 URL、许可证、版本、导入范围、依赖和移除步骤。 |
| 静态验证 | 检查包路径、资源引用、入口可达性、标记和来源记录。 |

## 工作方式

1. 读取目标 Android 项目的局部结构和规则。
2. 联网搜索 10–15 个候选仓库，并输出统一候选表。
3. 等待用户确认开源来源。
4. 输出实施预算，核对 Skill 规定的页面、资源、依赖和开关调用规模。
5. 再次等待用户确认实施方案。
6. 按来源划分独立功能子包，添加真实可达入口、统一总开关和 `Insert qc start/end` 标记。
7. 创建或更新 `docs/insert_qc_sources.md`，再做静态验证。

这个流程有两个明确确认点：选择来源后确认一次，实施预算后再确认一次。默认不执行 Gradle 构建；只有用户明确要求时才编译。

## 关键约束

- 尊重许可证并保留来源，不复制整个仓库。
- 不引入许可证不清晰、限制商用或具有不合适传染要求的来源。
- 不使用恒假条件、不可能字符串比较或隐藏分支制造“集成”。
- 危险权限、导出组件、宽泛 R8 规则、新 Maven 仓库或 Gradle 插件需要显式确认。
- 默认总开关方法为 `isInsertQcEnabled()`，默认关闭；所有新增入口都需要受控。
- Skill 自身规定了较高的“丰富集成”规模门槛；达不到时会回到候选选择，而不是静默缩减目标。

## 输出

最终交付包括选定来源、新增与修改文件、总开关位置和调用点、每个页面的可达路径、依赖/Manifest/R8/资源变化、来源清单、移除步骤、静态验证结果和未解决风险。

完整执行规则见 [SKILL.md](./SKILL.md)，候选与报告格式见 [output_templates.md](./references/output_templates.md)，筛选及集成约束见 [integration_rules.md](./references/integration_rules.md)。
