## 默认实施完成标准

| 项目 | 需要达到的结果 | 最小可观察验收 |
| --- | --- | --- |
| SDK/工具链 | 范围内 app compile/target 36，兼容工具链及必要 AndroidX API；保留业务身份、minSdk 和既有支持范围 | 配置差异；必要的受影响编译/资源/manifest 检查。版本按当前官方兼容表确认，不机械照抄 |
| 公共 insets | 统一基类或等效入口处理系统栏、cutout、侧边安全区及 IME；基于初始 padding；不无条件消费 insets | 重复派发不累积；顶部占位与真实 inset 一致；底部使用 max(导航安全区, IME)，不重复相加 |
| 表单与独立窗口 | 登录注册等表单可滚动；裁剪的 action bar 和内容均避让；隐私入口纳入系统栏处理；主题切换保持图标对比度 | 键盘显示时输入和提交可达；基类外页面有明确处理位置。实际视觉结果按授权单列 |
| 业务返回 | 用生命周期感知回调保留返回栈、取消裁剪结果、先取消选择、运动锁定和升级保护 | 状态 × 事件 × 期望结果矩阵；回调分发不递归。保护回调仅在对应工作状态或页面所有权期间生效 |
| BLE 密钥丢失 | API 36 广播按当前 BLE/classic 地址隔离；重复通知去重；恢复标志随进程重建保留；取消已排队任务并保护实际自动连接/配对/SPP 入口 | 规范化地址、无关地址隔离、重复丢失、恢复清除、持久化重建；保留主动操作入口；旧平台行为不被无关改写 |
| SDK 更新（条件项） | 已有依赖不兼容时才更新；同步包名/API、连接管理器与回调模型，防止切换设备后复用旧连接对象 | 已解析版本/API 证据、重复输入检查及受影响编译；连接回归与 JNI 运行单列。不得只替换库文件 |
| 健康及其他能力 | 按实际数据读写和调用链处理；已用 Health Connect 的项目保留数据兼容；未发现的问题不批量重写 | permissions、rationale、调用链及适用性证据；后台/LAN/Intent/媒体等按真实命中和风险处理 |
| 原生与产物（条件项） | 保留 ABIs；按实际交付的 arm64-v8a/x86_64 检查 16 KB；ARMv7 既有 4 KB 单独不提醒、不阻断 | ELF LOAD、RELRO、ZIP、AAB、运行分别记录；已有最终产物优先复用，无产物时明确未验证，不将 AAR 或文件名当作最终发布证明 |

布局实施遵循项目 RTL 规则；物理 cutout 左右边界保留物理方向，导航和日历随 RTL，时间轴保留业务语义。源码核对或构建通过不替代当前视觉证据。适配完成后停止默认范围的实施，不为补齐所有扩展设备场景持续扩大任务。

## 交付与停止条件

- 基础实现和约定的最小验证完成后，可以报告“API 36 基础适配已完成”，并列出所有剩余优化、未验证与条件风险。缺少扩展运行证据时用范围内的 `PASS_WITH_RISKS`，不可写“全面通过”。
- 将“适配实现状态”“当前提交阻断”“审核结果”分开。只有当前要求及相关证据充分时，才写“未发现本次适配引入的上架阻断，剩余优化不作为当前提交阻断”。必需提交项未验证时写“该项提交条件待核实”，不据此承诺可正常上架。
- 日期与设备类型按 [official-baseline.md](official-baseline.md) 的官方来源复核。政策截止日期尚未来临不等于已经支持 16 KB，也不消除真实运行崩溃；个别应用的 Console 状态需单独证据。
- 用户要求完整发布验收时才启用 [verification-and-release.md](verification-and-release.md) 的完整门禁。真实 P0/P1 或当前适用的提交要求不能因基础范围而隐去；未授权设备/视觉检查保持待验证，不探测设备或自动加依赖。
