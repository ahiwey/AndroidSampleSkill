# 产物与设备验收

## 最小构建与产物关联

- 分析现有产物时核对它对应的变体、源码和配置；文件名相同不证明是本次构建。记录必要的 APK 路径、哈希、包名、版本与 mapping 对应关系。
- 先确认真实任务名及项目并发/超时策略。规则解析或代码缩减可用目标 minify 任务；资源缩减和真机安装需目标 assemble 产物。保留签名、版本与用户数据，不擅自调整成另一个变体求通过。
- 运行一个必要验证后，只因失败、新修改或未覆盖风险追加构建；禁止 clean/循环重试。失败说明首个错误和是否由本次修改引入。
- 构建附带的 mapping/崩溃平台上传不等于本地校验，执行前检查任务图或已知项目配置，遵守外部写入授权。
- configuration.txt 检查最终规则来源、必要 consumer 与全局选项；mapping.txt 定位实际重命名；usage.txt 等移除记录定位裁剪；seeds.txt 等保留记录辅助解释。各文件只证明其覆盖范围，不把它们互相替代。
- 借助现有 APK/DEX 工具核验受影响类是否存活、名字是否必须稳定、必要字段/构造器/getter/setter 是否存在、泛型/运行时注解是否保留。结合 mapping 区分类重命名、合并与删除；没有 DEX 工具时明确检查缺口，不编造通过。
- 资源收缩检查最终 APK 与工具链资源报告，核对应用动态资源访问；代码 minify 通过不能代替资源验收。
- 留存与确切发布产物匹配的 mapping，异常时用相同版本 mapping retrace；不要拿下一次构建的 mapping 解读旧包。
- 体积比较保持同源码基线口径、同变体/签名配置、ABI、依赖和打包设置，分别说明 APK、DEX、资源指标。Debug 与 Release、不同 ABI 包不可直接作为优化收益基线；类重命名数量不是平台“混淆率”，未测性能不宣称启动/内存提升。

## 设备前置条件

已有本任务设备授权时不重问；没有时先完成独立工作再询问，不自动 ADB 探测或改用模拟器。授权后确认设备身份、安装包身份、前台状态、账号、外设和可用数据，再选择场景。

覆盖安装优先保留真实数据。签名不匹配时停止安装并说明；不要卸载或清数据强行通过。不改变无关权限、账号、绑定关系，也不触发 OTA/复位等未授权操作。

## 按风险挑选场景

| 风险 | 有意义的运行信号 |
| --- | --- |
| 反射网络模型/协程 | 真实相关响应成功解析；区分 HTTP 业务错误、认证/网络失败与反射异常 |
| 持久化兼容 | 同一安装数据从旧包升级后可读；不是仅空安装或只看缓存页面 |
| 字符串动画/反射 View | 实际触发受影响动画、页面或工厂，必要时对照前后截图；静态截图仅能证明该帧 |
| BLE/JNI/SDK | 外设连接、回调、解析/解码按具体修改验证；缓存设备名称或空录音页不算相关链路通过 |
| 资源缩减 | 动态资源、主题、WebView/skin 等受影响入口在最终包上出现 |
| 启动/生命周期 | 冷启动及相关前后台/重复进入行为；不以启动成功替代所有场景 |

- 每个关键场景记录“前置状态 × 操作 × 期望 × 观察结果”；样本、外设或账号不足标未验证。
- 日志限定包/PID和测试时间窗；涉及多进程时包括关联进程。必要时结合 crash buffer、退出原因、ANR 和完整异常栈，避免只取最后少量日志遗漏早期崩溃。
- 排查 ClassNotFound/NoSuchMethod/NoSuchField、反射调用、JsonData/TypeToken、VerifyError、UnsatisfiedLinkError 等线索，但系统信息日志中出现异常字样不等于本应用崩溃。用栈、调用和产物证据判断。
- 原有业务缺陷与 R8 回归分别记录。没有证据时说“原因未定”，不要通过关闭混淆或扩大无关修复掩盖问题。
- 测试结束清理仅本次创建的临时文件，恢复经授权改动的测试状态并核对；不删除用户原有数据。

## 交付

说明修改文件、必要规则的理由、准确验证命令/结果、最终包/映射位置和未覆盖场景。分别标注静态、构建、产物、安装、运行阶段；“已安装”需实际安装证据，“未发现崩溃”限定到所测场景与时间窗。不要承诺零崩溃或用结构 A+ 代替运行安全结论。
