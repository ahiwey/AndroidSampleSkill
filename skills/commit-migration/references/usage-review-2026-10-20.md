## 代表案例与验证口径

[migration-regressions.json](../evals/migration-regressions.json) 的 8 个合成案例覆盖小改、工具缺失、编码/用户改动、API/数据库/R8、宿主恢复、提交筛选、状态与返工、续做和验证授权。逐案进行离线决策推演，检查是否能得出可执行的范围、工具路径、保留项和验收边界。它是可复用评审输入，不是自动通过的模型基准。

本轮主代理逐案推演结果如下；这不是独立盲测，也没有实际修改案例中的 Android 项目：

| 案例 | 具体决策与验收边界 |
| --- | --- |
| 1 小改 | 只改日期解析及核对实际日期消费者；跨午夜开始日期应为 10 月 19 日，同日仍为 10 月 20 日。保留结束日期与其他用户文件，仅静态验证。 |
| 2 工具缺失 | 已知所选解释器缺模块后，直接用 Git/rg、XML 和哈希补齐映射；共享字符串按 hunk 合并。当前仅交付宿主/依赖方案，无写入或构建。 |
| 3 编码 | 必须同时保留 `设置与通知`、UTF-8 BOM、CRLF 和 `%1$d`，并核对新增中文原文；仅通过 XML 解析不足，不能整文件 restore。 |
| 4 数据/API | 目标版本应是 8，注册 7→8 无损迁移；JSON 数组不走逗号切割。旧报告继续可读，能量模块排除；复核自定义 R8 文件及 consumer 规则，不凭 debug 测试声称 release/运行已验证。 |
| 5 宿主 | 使用明确的 RecordingList 映射，保护 RecordList；稳定 ID/tag 复用恢复实例。Activity/独立 Fragment 的标题所有权分别处理，保留 tint 和 view 生命周期清理，不接 MainActivity。 |
| 6 提交 | 固定选择集，按 C1→C2 依赖顺序迁移全部录音 hunk 及必要 R8，排除同文件里的卡片；不覆盖目标已有恢复队列，也不复制版本/签名。 |
| 7 状态/返工 | 将偏好值更新与两个缓存标签消费者刷新分开核对；把一次逻辑请求与重试 attempt 分开计数，先对比脱敏输入，不能无证据调超时。当前只查证和方案。 |
| 8 续做 | 核对原 S/hash 与当前 diff 后，只补两个调用方并检查新差异；识别代码仍注释。不得继承别的会话设备权限，也不得将先前方案算成已安装或运行。 |

结构检查使用 UTF-8 模式运行 `quick_validate.py`，另检查本技能内 Markdown 链接/锚点、8 个案例 JSON 及固定 30 个唯一会话 ID。Windows 默认编码下校验器曾报 GBK 解码错误，切换解释器 UTF-8 模式解决；未改动系统校验器或以重编码技能文件规避。

本次未运行独立模型对照、真实 Android 迁移、Gradle、设备或截图验收。历史会话中的构建/真机结论只作为历史交付记录，不复用其设备授权，也不表述为本次重新验证。Skill 的 frontmatter、链接、JSON、差异检查与同步哈希可验证结构和发布一致性；不能证明未来迁移成功率或耗时改善，暂不提供百分比或 A+ 评级。
