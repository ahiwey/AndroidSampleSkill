# 智能体工作流优化

`optimize-agent-workflow` 用于审计近期 Codex、WorkBuddy 或其他编码智能体任务，并用证据驱动的小改动减少返工、耗时、无效工具调用和 Token 消耗。

## 何时使用

- 复盘最近一段时间的智能体任务质量和效率。
- 查找重复搜索、重复读取、无必要构建或多轮澄清问题。
- 改进 `AGENTS.md`、`MEMORY.md`、Prompt 或团队协作流程。
- 评估某个重复工作流是否应该沉淀为 Skill。
- 建立可量化的下一轮持续优化基线。

## 快速使用

```text
使用 $optimize-agent-workflow 审计最近 14 天的 Codex 任务，找出最主要的返工和工具浪费原因；只实施有重复证据支撑、可逆且低风险的规则改进。
```

限制为报告、不修改规则：

```text
使用 $optimize-agent-workflow 复盘最近 20 个有效任务，只输出证据表、优先级建议和下一轮指标，不修改任何文件。
```

## 审计内容

| 维度 | 检查内容 |
| --- | --- |
| 需求质量 | 背景、约束和成功标准是否明确，澄清是否集中。 |
| 返工 | 后续轮次是否因为遗漏原始要求、约束或验证目标。 |
| 工具效率 | 是否重复搜索、重复读取、过度规划或执行无必要构建。 |
| 验证质量 | 视觉、异步、缓存和生命周期问题是否有匹配的运行时证据。 |
| 规则质量 | 是否冲突、重复、过于模糊或无法验证。 |
| 复用机会 | 重复流程是否适合整理成专用 Skill。 |

## 工作方式

1. 默认选择最近 14 天或 20 个有效任务作为有界样本。
2. 从任务历史、终端输出、差异、失败记录和现行规则中建立证据表。
3. 将结论标记为已确认、证据支持的推断或未验证，不虚构 Token 数和节省比例。
4. 为候选改进给出证据、收益、代价、验证方法、`P0/P1/P2` 优先级和类型。
5. 只实施小范围、低风险且可逆的改进；证据较弱时改为最小实验。
6. 若改动通用规则，区分项目事实与可复用行为，并按条件同步 AndroidEasyRules。
7. 定义 3–5 个下一周期指标和决策阈值，留出可比较的基线。

## 典型输出

- 审计范围与证据充分性。
- 3–7 个最重要发现及其优先级。
- 已实施的规则、Prompt 或流程改动。
- 验证命令与结果。
- 延后事项和原因。
- 下一轮指标、基线、阈值、采集方法和复盘窗口。
- 改进后的通用、Quick 和专用任务 Prompt 模板。

该 Skill 不会自动安装插件、连接账号、删除数据或发布内容。发现值得复用的新 Skill 时只会先建议；得到用户批准后，才会在 `AndroidSampleSkill/skills/<skill-name>/` 中创建并验证。

完整规则见 [SKILL.md](./SKILL.md)，指标设计见 [measurement-loop.md](./references/measurement-loop.md)。
