# 状态与常规行为

按变化读取，不为普通静态布局枚举所有状态。沿用入口短表，不再建第二套映射。
用户说明、现有业务、原型证据优先于惯例；相互冲突且影响业务时确认。静态图不能证明交互，推断简记后继续。
多张图可对应同页的连接、布局、数据或折叠状态，不各建一套。已有稳定的状态逻辑直接复用。
state_map.mjs 仅在可信图层数据现成且人工难区分时使用；不能为调用脚本先生产图层数据。

- 普通卡片进入详情，加号进入添加；已有页则复用。传递现有路由要求的对象 ID、日期或设备上下文，不能只打开目标页却丢失所选对象。
- 更多/展开按明确证据选完整列表或原地展开；没有证据时预览卡片的“更多/查看全部”可默认进入完整列表，显式可折叠内容才默认原地展开，并说明推断。
- 预览数量优先沿用已有规则，否则按设计可见数量决定；它是上限，不能只在恰好等于该数量时展示。超出才显示更多；不足不显示无意义入口。
- 零数据隐藏整卡或显示空态取决于组件语义，不把具体页面规则推广全项目。
- 示例数据不能硬编码为业务规则；名称近似不代表数据源相同。
- 真实业务含义或写入契约不明确才集中询问，不阻塞其他页面。

仅对修改的逻辑检查必要边界：列表为零条、少于上限、达到上限、超出上限；折叠为下滑收起、上滑恢复及切视图后的状态。优先通过代码或聚焦测试判断，无需为每个数值制造真机截图。
切设备/日期时不得显示旧对象内容；新增异步逻辑才列最小“状态 × 事件 × 期望输出”矩阵。
对范围内每个动作串起“入口 → 参数/设备/日期 → 目标状态 → 保存或取消 → 返回刷新”；设置箭头、独立展开、弹窗关闭不能只画不接。保存失败不能当成功返回；优先复用现有错误处理。
有真实添加实现时，保存后用现有机制刷新来源页；取消返回不凭空新增。空页返回不模拟数据变化。
纯逻辑变化按需测过滤、排序、阈值和隔离，不为样式堆测试。
新增或修改请求生命周期时，从实际风险挑选重复提交、取消、切对象后的迟到响应、失败重试及原请求关联的最小用例；区分“pending 外观 fixture”与真正驱动请求/回调的测试。已有逻辑只读核查不等于发现缺陷；无测试证据记未覆盖，不据此宣称存在竞态。优先用现有 fake/可隔离纯逻辑，不自动新增测试依赖。

空页仅用于用户允许暂缺内容的下游页；不能代替本次要求实现且已提供设计的页面。
按项目 Activity/Fragment/路由体系创建，保留标题、返回能力、内部注册及索引。
不增加保存成功、存储或 API；交付写“入口已接通，内容待实现”。
