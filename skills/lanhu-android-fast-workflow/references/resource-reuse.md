# 公共组件与资源复用

只在本轮涉及公共组件、背景调整或素材替换时读取。项目已有截图/图片专项规则时以其为准，复用主流程短表，不再另建审计报告。

## 先定复用范围

- 查同职责组件及真实调用：按钮、日期/时间/分钟选择器、输入项、卡片、类型名称与图标映射。外观相同且行为契约一致才共用；添加/编辑通常复用布局与状态。
- 在短表标明“原样复用、调整公共样式、替换公共素材、局部新增”。只有颜色或圆角差异时，优先已有语义色、style、drawable；确认没有合适实现才最小新增。
- 用户明确要求公共替换或已确认方案覆盖公共修改时直接执行，不重复确认。只要求某页还原时，先按实际引用评估；会改变范围外页面就用局部样式，确需扩大时只确认增量范围。

## 同名替换检查

1. 沿实际资源名找定义、别名、selector、style 和 XML/代码调用；只追相关引用。按项目实际存在的 source set、flavor、密度、night、主题/皮肤检查同名变体，防止更高优先级的旧图遮盖新图。
2. 查看新旧图的格式、像素尺寸、逻辑尺寸、透明边距、背景及选中/禁用等状态。保留资源类型和名称；不把一张 xxhdpi 图原样复制到所有密度目录，不擅自删除旧变体。缺失变体保留并说明覆盖边界，不能声称全局替换完成。
3. 核对调用方 tint、alpha、padding、scaleType、固定尺寸、compound drawable 和最小触控区。切图自带背景时避免再包同样背景；多彩图标不套单色 tint。保留 View 类型/id、点击回调及可访问性语义，避免样式替换破坏绑定或强制类型转换。
4. 原素材和未提交修改可追溯；只导入实际引用的新素材，不覆盖无关资源。完成后按实际改动核对变体；运行态抽查目标页及一个不同使用页前，遵循主流程的自动化验证询问规则。

## 背景颜色与透明度

- 记录底色、图层不透明度和圆角的依据。背景 7% 不透明度应作用于背景色/drawable，不把整个卡片 View 的 alpha 设为 7%，以免文字和图标一起变淡。
- 颜色 alpha、drawable alpha、View/父容器 alpha 可能叠乘，先查现有实现，不重复应用设计稿同一透明度。已知底色时优先用原始色与 alpha；截图取样是合成色，不直接当作半透明层原始色。
- 复用已有主题色、形状和选中背景，按影响范围调整。形状/圆角可共用而颜色角色保留参数差异；不同业务语义的卡片不因看起来接近就强行共用一个全局背景。

## 最小验证

检查真实引用与限定目录、图片可解码和尺寸、XML/资源链接（必要时）、公共调用方类型契约。本次已同意自动化验证且可运行时，在相同主题/密度/状态下比较代表页并抽查其他使用页；跳过、未授权或无法运行均明确标注运行态/视觉未验证。编译成功不证明图片匹配或公共替换覆盖完整。

## 应用证据，不以“已复制”验收

主流程短表补“资源名 → 实际 XML/绑定位置 → 变体/tint → 静态或视觉证据”。可见元素逐项核对，缺图及仅导入未绑定都保留为未完成项。
颜色先解引用到实际值及作用对象，再判断共用；不能凭资源名语义套用不同色系，更不能把整行文字都染为指标色。布局与颜色细则见 [视觉契约](visual-contract.md)。

```powershell
python "<skill-root>/scripts/resource_usage.py" --resource drawable/ic_metric --resource color/text_secondary --scope "<page.xml>" --scope "<binding.kt>" --res "<module/src/main/res>" --limit 12
python "<skill-root>/scripts/resource_usage.py" --scope "<page.xml>" --node-id score_card --limit 12
```

工具只读取明确的文件和 res 根目录，输出资源定义/限定符、引用行、布局方向/约束/换行与子节点；--node-id 定位子树，--scope 与 --res 可重复指定。只运行本轮难以人工一次核对的批量项。
工具保留 style item 名、有限继承、颜色别名链、目标祖先和 include 候选；--node-id 不丢失父布局证据。注释排除，tools 预览引用单列。res 根/限定符是候选，不自动选择生效变体；主题、selector、adapter/动态映射和歧义仍需核实。not_found_in_scope 仅表示给定范围未命中，不能据此删资源或断言全仓未使用。工具不自动修改、生成素材或选择运行态变体。
